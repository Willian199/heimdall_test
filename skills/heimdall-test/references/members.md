## Usage

| Entry point | Subjects |
| --- | --- |
| `Heimdall.members()` | Fields, methods, constructors |
| `Heimdall.fields()` | Field declarations |
| `Heimdall.methods()` | Method declarations |
| `Heimdall.constructors()` | Constructor declarations |
| `Heimdall.codeUnits()` | Methods and constructors |

These scopes use `ClassMember` nodes from imported type bodies. Top-level functions are not methods or code units. Start with the narrowest scope rather than selecting all members and manually testing their runtime types.

Existing DSL families cover names, paths, annotations, owner declarations, kinds, declared/return/parameter types, required and optional parameters, constructor and method calls, and field accesses. Owner filters include `areDeclaredInClassesThat(...)`; kind filters use `areOfKind(MemberKind...)` and conditions use `beOfKind(MemberKind...)`.

```dart
Heimdall.constructors()
    .that()
    .resideInPath('src/factories/**')
    .should()
    .beOfKind(MemberKind.factoryConstructor)
    .check(project)
    .assertNoFindings();
```

This example requires every constructor under `lib/src/factories/` to be a factory constructor, assuming `importPath()`. Change the path to the area where your project requires this convention.

Prefer built-in call/type/ownership checks before traversing bodies. When custom behavior remains necessary, use cached `owner`, `parameters`, `executableRoots`, annotations, and locations. A field declaration can contain several variables; use the per-variable collections described in [cached model data](cached-model-data.md) for individual field visibility.
